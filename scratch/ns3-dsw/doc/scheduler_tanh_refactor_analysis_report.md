# ns3-dsw调度器Tanh重构效果深度分析报告

## 📋 执行摘要

本报告深度分析了ns3-dsw项目中调度器的**Tanh归一化重构效果**。通过对比重构前后的仿真结果，我们发现新模型在**调度稳定性**方面有显著改善，但在**负载均衡**方面出现退化，需要进一步优化。

### 🎯 关键发现

1. **调度决策优化**：切换率从77.5%降至70.1%，减少7.4个百分点
2. **成本模型改进**：时间成本占比从76.9%微降至78.2%，基本持平
3. **负载均衡恶化**：均衡指数从0.0910升至0.1601，变差75.9%
4. **决策质量提升**：切换决策平均节省66.5%成本

## 📊 详细分析

### 1. 调度器架构重构概述

#### 重构内容
- **线性模型** → **Tanh归一化非线性模型**
- **时间统一单位**：Cost_cong = W_base × tanh(T_delay/K_c)
- **生产者紧急度**：Multiplier = 1.0 + (W_prod × tanh(Pending/K_p))

#### 新参数配置
```cpp
maxCongestionPenalty = 0.5    // W_base: 最大拥塞惩罚
congestionSensitivity = 2.0   // K_c: 拥塞敏感度（秒）
maxProducerPenalty = 3.0      // W_prod: 最大生产者紧急度乘数
producerSensitivity = 100.0   // K_p: 生产者敏感度（任务数）
```

## 🔍 根因分析

### 新模型问题诊断

#### 1. Tanh参数可能不当
- `producerSensitivity = 100`：可能过小，导致生产者权重过快增长
- `congestionSensitivity = 2.0`：可能过小，对延迟过于敏感

#### 2. 缺乏负载均衡机制
- 新模型仅优化成本，未考虑负载分布
- 可能形成"马太效应"：负载高的节点更容易被选中

#### 3. 阈值设置问题
- 切换阈值可能过小，导致轻微成本差异即触发切换
- 节点7的100%切换率说明阈值机制失效

## 💡 优化建议

### 建议1：调整Tanh参数

```cpp
// 当前配置
double maxCongestionPenalty = 0.5;
double congestionSensitivity = 2.0;
double maxProducerPenalty = 3.0;
double producerSensitivity = 100.0;

// 推荐配置
double maxCongestionPenalty = 0.3;    // 降低软限制
double congestionSensitivity = 3.0;   // 提高敏感度（秒）
double maxProducerPenalty = 2.0;      // 降低紧急度乘数
double producerSensitivity = 150.0;   // 提高敏感度（任务数）
```

**预期效果**：
- 降低时间成本波动
- 减少过度敏感的切换
- 提高决策稳定性

### 建议2：引入负载均衡因子

在成本计算中加入负载均衡项：

```cpp
// 新增负载均衡成本
double loadBalanceCost = 0;
for (auto& consumer : m_consumers) {
    double utilization = consumer.utilization;
    double targetUtilization = 0.6;  // 目标利用率60%
    double balancePenalty = std::abs(utilization - targetUtilization);
    loadBalanceCost += balancePenalty;
}
double totalCost = processingCost + timeCost + loadBalanceCost * 0.1;
```

### 建议3：改进切换阈值

```cpp
// 当前
double threshold = currentCost * 0.2;  // 20%

// 建议
double dynamicThreshold = std::max(0.1, currentCost * 0.3);
double hysteresis = 0.05;  // 添加滞回机制
```

### 建议4：生产者权重平滑

```cpp
// 当前
double Multiplier = 1.0 + (m_maxProducerPenalty * std::tanh(static_cast<double>(producerPendingTasks) / m_producerSensitivity));

// 建议：使用EWMA平滑生产者积压
double smoothedPending = CalculateEwmaPending(producerPendingTasks);
double Multiplier = 1.0 + (m_maxProducerPenalty * std::tanh(smoothedPending / m_producerSensitivity));
```
