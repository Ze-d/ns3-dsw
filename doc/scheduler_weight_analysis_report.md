# ns3-dsw 价格感知调度器生产者队列权重分析报告

## 执行摘要

本报告分析了当前价格感知调度器的权重配置合理性，重点关注**生产者队列权重**对调度决策的影响。分析发现，当前配置存在**过度惩罚**问题，导致调度器过度关注生产者积压而忽视电价差异，违反了价格感知调度的核心目标。

**关键发现**：
- 队列惩罚占总成本的 **74.16%**，最高达 **99.09%**
- 生产者最大积压达 **466 个任务**，平均 **246 个任务**
- 当前权重配置导致 **200 个待处理任务 ≈ 15.4 的电价差异**，惩罚过于严重

**建议优化**：采用组合方案，将 `queuePenaltyFactor` 从 0.1 降至 0.03，`producerWeightFactor` 从 0.15 降至 0.05。

## 1. 调度器工作原理与成本模型

### 1.1 调度器核心逻辑

价格感知调度器 (`PriceAwareScheduler`) 在任务到达时计算所有消费者的调度成本，选择成本最低的消费者。核心成本计算公式为：

```cpp
totalCost = processingCost + (timeCost * producerWeight)

其中：
processingCost = price * processingTime
timeCost = (TTTT + queueWaitTime) * queuePenaltyFactor
producerWeight = 1.0 + pendingTasks * producerWeightFactor
```

### 1.2 当前权重配置

代码位置：`scratch/ns3-dsw/src/topo_figure_flowmon_cfg_integrated.cc:292-294, 538`

```cpp
double queuePenaltyFactor = 0.1;      // 队列积压惩罚系数
double loadDecayFactor = 0.5;          // 负载衰减因子
double producerWeightFactor = 0.15;    // 生产者压力权重因子
```

当前配置中，200 个 pending 任务的含义：

```
producerWeight = 1 + 200 × 0.15 = 31
```

这意味着：
- 时间成本被 **放大 31 倍**
- 调度器会 **强烈倾向** 选择处理速度快的节点
- 即使电价便宜 50%，也可能被忽视
- **完全违背了"价格感知"的设计初衷**

**现实类比**：如同为了避免超市排队（3分钟等待），宁愿花更多钱（贵15元）在附近便利店购买。

## 4. 问题识别

### 4.1 核心问题

#### 问题1：队列惩罚过重
- **当前值**：`queuePenaltyFactor = 0.1`
- **影响**：队列惩罚占总成本的 74.16%
- **后果**：调度器过度关注队列长度，忽视电价差异

#### 问题2：生产者权重增长过快
- **当前值**：`producerWeightFactor = 0.15`
- **影响**：200 个 pending 任务 → 权重 31 倍
- **后果**：轻微积压就导致调度器疯狂切换目标

#### 问题3：负载分布不均
- **表现**：生产者积压差异巨大（59-466 个任务）
- **后果**：
  - 部分消费者满载，部分空闲
  - 队列长度剧烈波动
  - 调度器频繁切换，增加网络开销

### 4.2 根本原因

**权重配置失衡**：
- 队列惩罚因子（0.1）过大
- 生产者权重因子（0.15）增长过快
- 两者叠加导致时间成本远超处理成本

**调度逻辑缺陷**：
- 缺乏平滑的权重调整机制
- 未考虑任务的紧急程度差异
- 切换成本未被充分建模

### B. 成本计算公式详解

**完整成本计算流程**：
```cpp
CostMetrics CalculateCost(...) {
    // 1. 预测TTTT（总任务传输时间）
    predictedTTTT = PredictTTTT(consumer);

    // 2. 计算队列等待时间
    queueWaitTime = smoothedQueueLength * processingTime;

    // 3. 计算处理时间（考虑负载衰减）
    effectiveRate = tasksPerSecond * (1 - utilization * loadDecayFactor);
    processingTime = 1 / effectiveRate;

    // 4. 计算任务开始时间
    startTime = arrivalTimeAtConsumer + queueWaitTime;

    // 5. 获取电价
    price = GetPriceAtTime(startTime, phaseOffset);

    // 6. 计算处理成本
    processingCost = price * processingTime;

    // 7. 计算时间成本
    timeCost = (predictedTTTT + queueWaitTime) * queuePenaltyFactor;

    // 8. 计算生产者权重
    producerWeight = 1.0 + pendingTasks * producerWeightFactor;

    // 9. 总成本
    totalCost = processingCost + (timeCost * producerWeight);
}
```
